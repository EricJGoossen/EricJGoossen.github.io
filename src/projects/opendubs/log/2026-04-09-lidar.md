Optical flow only says how far the robot has moved, so it drifts. For an absolute position and a map, the base carries two RPLIDAR A1 2D lidars, one at the front and one at the back. Bringing them up was mostly fighting USB: the two units have identical USB IDs, so I wrote udev rules that name each one by the physical hub port it's plugged into, and powering both at once timed one of them out, so they now start a few seconds apart.
{% endrow %}

{% placeholder "Merged scan or map in RViz" %}

Mapping and Nav2 expect a single scan, so I wrote a node that merges the two. It pairs a front and a back scan taken within 0.1 s of each other, resamples both to the finer of their two angular resolutions, moves every return into the robot's frame using the TF tree, and re-bins them into one 360° scan, keeping the nearest return in each direction. Returns closer than 20 cm, which hit the robot itself, are dropped. The merged scan feeds slam_toolbox for mapping, and Nav2 for navigation. {# Placeholder: Nav2 details and results #}
