Optical flow drifts, so for an absolute position and a map, the base carries two RPLIDAR A1 2D lidars, one at the front and one at the back. Bringing them up was mostly fighting USB: the two units have identical USB IDs, so udev rules name each by the hub port it's plugged into, and they power up a few seconds apart so neither times out.
{% endrow %}

{% row "images/sim-slam-nav2.mp4", "Top-down view of a simulated lab room being mapped: the robot, a small white rectangle, follows green Nav2 plans to a series of goal stars while its front lidar (orange) and back lidar (blue) light up the walls, and the grey map of the room fills in behind it", { poster: "images/sim-slam-nav2.jpg", caption: "A replay in Gazebo: my URDF, lidar merger and slam_toolbox settings, unmodified, mapping a made-up lab room while Nav2 drives. 6× speed." } %}
Mapping and Nav2 expect one scan, so I wrote a node that merges the two: it pairs scans taken within 0.1 s, moves every return into the robot's frame, and keeps the nearest return in each direction of one 360° scan, dropping hits on the robot itself. On top of it, I set up slam_toolbox and Nav2, which drove the robot point to point in simulation.
{% endrow %}
