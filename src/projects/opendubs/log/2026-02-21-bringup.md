OpenDubs runs on an NVIDIA Jetson Thor, so the first job was getting it ready for the whole team. I flashed JetPack onto the Thor, got its IO talking to the rest of the robot, and set up the Docker environment we all develop in: a ROS 2 image with the build tools, a Makefile and VS Code tasks to build, run and debug inside it, and per-person git identities so four people could commit from one shared machine without their names getting mixed up. Everything after this was built and run inside that container.
{% endrow %}

{% row "images/base-frame-cad.jpg", "A CAD render of the robot's square aluminum base frame with a mecanum wheel at each corner and four vertical posts", { caption: "The mecanum base. CAD render from the lab's build guide." } %}
The base drives four mecanum wheels through a Pixhawk running ArduPilot, which ROS talks to over MAVROS. With another intern, I brought up the low-level drive code, which turns velocity commands into RC overrides, with PID loops and watchdogs on the radio and the IMU. Around it I added what the rest of the stack needed: a URDF and an SDF of the robot with collision geometry, so it shows up correctly in RViz and in Gazebo; a robot state publisher; a debug mode in the main launch file; and a ROS service that records chosen topics to rosbags, capped at five minutes per bag. Every test after this, starting with localization, was a recorded bag I could replay and compare.
{% endrow %}
