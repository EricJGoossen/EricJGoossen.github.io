{% row "images/harness-diagram.svg", "Diagram of the harness: YAML configs feed run_eval.py, which drives the DROID robot and asks one policy client for chunks of actions; the client reaches π0 and π0.5 over WebSocket, GR00T N1.7 over ZMQ and MolmoAct2 over HTTP; every rollout's scores and videos go to a results folder that compute_results.py turns into CSVs", { caption: "How a run fits together." } %}
Every VLA ships its own server, and they don't agree on how to talk: openpi's π0 and π0.5 use WebSockets, GR00T uses ZMQ and MolmoAct2 uses HTTP. I wrote [one harness](https://github.com/EricJGoossen/VLA_benchmarking) that hides all of that behind a single interface: a new model, task or whole benchmark is a short YAML file, not new code.
{% endrow %}

{% row "images/rollout-banana-plate-pi05.mp4", "A Franka Panda arm running π0.5 picks up a banana and drops it on a white plate", { poster: "images/rollout-banana-plate-pi05.jpg", caption: "π0.5 putting the banana on the plate.", more: [{ src: "images/rollout-block-basket-pi05.mp4", poster: "images/rollout-block-basket-pi05.jpg", alt: "The Franka arm running π0.5 picks up a small blue block and moves it to an orange basket", caption: "π0.5 on the block and basket." }] } %}
On the robot, the harness asks the policy for a chunk of actions, runs eight of them open loop, then asks again, recording the scene and wrist cameras throughout. The operator scores each rollout, everything is saved as it goes so an interrupted run resumes, and one script turns the results into success rates per task and per prompt.
{% endrow %}
